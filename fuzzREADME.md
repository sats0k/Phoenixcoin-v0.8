# Fuzz Tests

Phoenixcoin includes four libFuzzer targets:

- `fuzz_MLDSASigner_deserialize`
- `fuzz_encrypted_keys`
- `fuzz_hybrid_verify`
- `fuzz_hybrid_message_parse`

`fuzz_hybrid_message_parse` fuzzes the pure v1 `HYBS` message-container
parser (`ParseHybridMessage` in `src/hs/hybrid_message.cpp`) with arbitrary
bytes. Sanitizers detect crashes, out-of-bounds reads, and excessive/duplicate
allocations; an in-target assertion pins the parser's contract: a successful
parse yields exactly the fixed ML-DSA-65 pubkey/signature sizes, and a
rejected input leaves every output empty (no partially accepted data).

Run the commands below from the Phoenixcoin repository root.

## Requirements

You need:

- Clang with libFuzzer support
- CMake
- Git

The fuzz build uses Clang/Clang++ rather than GCC/G++ because GCC does not support `-fsanitize=fuzzer`.

## 1. Get secp256k1

The Git repository does not contain the `src/secp256k1` source tree. Clone the upstream Bitcoin Core secp256k1 repository into that exact directory:

```bash
git clone https://github.com/bitcoin-core/secp256k1.git src/secp256k1
```

If `src/secp256k1` already exists, make sure it is a valid secp256k1 checkout.

Verify it with:

```bash
ls src/secp256k1
```

You should see directories/files such as `src`, `include`, `configure.ac`, and `CMakeLists.txt`.

## 2. Configure and build

From the Phoenixcoin repository root:

```bash
cmake -S . -B build-fuzz \
  -DCMAKE_C_COMPILER=clang \
  -DCMAKE_CXX_COMPILER=clang++ \
  -DCMAKE_BUILD_TYPE=Debug \
  -DENABLE_FUZZ=ON
```

Build:

```bash
cmake --build build-fuzz -j$(nproc)
```

The fuzz executables are:

```text
build-fuzz/fuzz_MLDSASigner_deserialize
build-fuzz/fuzz_encrypted_keys
build-fuzz/fuzz_hybrid_verify
build-fuzz/fuzz_hybrid_message_parse
```

## 3. Quick smoke tests

Run 1,000 iterations of each target first:

```bash
./build-fuzz/fuzz_MLDSASigner_deserialize -runs=1000
./build-fuzz/fuzz_encrypted_keys -runs=1000
./build-fuzz/fuzz_hybrid_verify -runs=1000
./build-fuzz/fuzz_hybrid_message_parse -runs=1000
```

A successful run should finish with `DONE` and no sanitizer error or crash.

## 4. Run a longer fuzzing campaign

Create corpus directories:

```bash
mkdir -p fuzz-corpus/mldsa-deserialize
mkdir -p fuzz-corpus/encrypted-keys
mkdir -p fuzz-corpus/hybrid-verify
mkdir -p fuzz-corpus/hybrid-message-parse
```

A small structured corpus covering valid containers, per-field truncations,
bad magic/version, `0xFFFF` length fields, and trailing bytes is a good seed
for `fuzz_hybrid_message_parse`.

Run each target for one hour:

```bash
./build-fuzz/fuzz_MLDSASigner_deserialize \
    fuzz-corpus/mldsa-deserialize \
    -max_total_time=3600
```

```bash
./build-fuzz/fuzz_encrypted_keys \
    fuzz-corpus/encrypted-keys \
    -max_total_time=3600
```

```bash
./build-fuzz/fuzz_hybrid_verify \
    fuzz-corpus/hybrid-verify \
    -max_total_time=3600
```

```bash
./build-fuzz/fuzz_hybrid_message_parse \
    fuzz-corpus/hybrid-message-parse \
    -max_total_time=3600
```

The corpus is retained and can be reused by later runs.

## 5. Leak checking

For example, run the hybrid verifier with LeakSanitizer enabled:

```bash
ASAN_OPTIONS=detect_leaks=1:leak_check_at_exit=1 \
./build-fuzz/fuzz_hybrid_verify -runs=10000
```

A clean run should produce no sanitizer report or crash.

## 6. If a crash is found

Keep the crash input generated by libFuzzer. It can be reproduced with the corresponding fuzz executable. libFuzzer normally prints the artifact filename, for example:

```text
Test unit written to ...
```

Do not delete the artifact; it is needed to reproduce and debug the failure.

## Notes

- Build fuzz targets with Clang/Clang++, not GCC/G++.
- Do not use `-fsanitize=fuzzer` with GCC.
- `SANITIZER_FLAGS` must be handled by the project's CMake configuration; passing an unused `-DSANITIZER_FLAGS=...` option produces a CMake warning.
- The `src/secp256k1` checkout is required by the fuzz build but is not stored in the Phoenixcoin Git repository.
